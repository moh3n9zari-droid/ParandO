1. MISSION OVERVIEW & ROOT CAUSE REMEDIATION
--------------------------------------------------------------------------------
Objective:
Correct the process-termination escalation defect in the production smoke test
harness, prove deterministic cleanup on both success and failure paths, verify
the full local CI sequence, and provide an accurate CI status report.

Root Cause Analysis of the Escalation Defect:
In Node.js, `child.killed` indicates only whether `child.kill()` was invoked on the
Node.js ChildProcess wrapper; it does NOT prove or indicate that the child process
has actually terminated in the operating system.
Previously, the escalation check evaluated `!child.killed` before sending `SIGKILL`.
Because the initial graceful `SIGTERM` caused `child.kill('SIGTERM')` to be called,
`child.killed` was set to `true`. When the escalation timer subsequently fired:
1. `!child.killed` evaluated to `false`.
2. `killProcess` had an early return `if (child.killed) return;`.
Consequently, the forced-termination escalation path was blocked from dispatching
`SIGKILL`, leaving stubborn or unresponsive processes running in the OS indefinitely.

Corrective Engineering Applied:
1. `isProcessAlive(child)` introduced:
   - Completely removes reliance on `child.killed`.
   - Checks `child.exitCode === null && child.signalCode === null`.
   - Probes the OS kernel via `process.kill(child.pid, 0)`: returns true if the
     OS process exists, false on `ESRCH`.
2. `sendSignal(child, signal)` hardened:
   - Does not check `child.killed`.
   - Dispatches `signal` to the detached process group (`process.kill(-child.pid, signal)`).
   - Gracefully falls back to direct PID signaling if process group signaling fails.
   - Allows successive signals (e.g. `SIGTERM` followed by `SIGKILL`).
3. `terminateServerGracefully(child, signal, timeoutMs)` refactored:
   - Checks `isProcessAlive(child)`. If already exited, immediately resolves with recorded state.
   - Employs dedicated `escalationDelayMs` (50% of timeout).
   - If child remains alive after graceful `SIGTERM`, dispatches `SIGKILL` and flags `escalated = true`.
   - Bounded hard timeout (`timeoutMs`) prevents indefinite hangs.
   - Cleans up event listeners and timers upon resolution to prevent memory leaks.
4. Asynchronous Failure-Path Cleanup (`cleanupAllAsync`):
   - Dispatches `SIGKILL` to all remaining alive child process groups.
   - Bounded wait (up to 3000ms) polls until OS processes exit.
   - Top-level `.catch()` logs the primary test error first, awaits `cleanupAllAsync()`,
     and only then terminates with `process.exit(1)`.
5. Dedicated Regression Test Suite (`scripts/test_termination_escalation.ts` & Test 12 in `scripts/production_smoke.ts`):
   - Synchronizes on child readiness (`STUBBORN_READY`) to eliminate signal-registration race conditions.
   - Tests that a process trapping and ignoring `SIGTERM` is forcefully terminated by `SIGKILL`.
   - Asserts `escalated === true`, `signal === 'SIGKILL'`, and `!isProcessAlive(stubborn)`.
   - Tests already-dead child handling without hangs.

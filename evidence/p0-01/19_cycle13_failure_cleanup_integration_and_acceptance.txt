1. MISSION OVERVIEW & ROOT CAUSE REMEDIATION
--------------------------------------------------------------------------------
Objective:
Resolve the P0-01 verification gap where `SMOKE_FORCE_FAIL=1` in `scripts/production_smoke.ts`
previously triggered an exit before the production server was spawned, thereby failing to prove
cleanup of an actively running production server after test failure. Add a deterministic integration
test harness verifying that when a controlled assertion failure is induced strictly AFTER server
readiness, the production server, its process group, and all child processes are completely
terminated, listening ports are released, and errors are cleanly observable without concealment.

Root Cause Analysis:
Previously, the controlled negative trigger `if (process.env.SMOKE_FORCE_FAIL === '1')` was positioned
at line 411 in `scripts/production_smoke.ts`, right before dynamic port allocation and server spawning.
Consequently, invoking the negative check exited before `spawnProductionServer(port)` was called.
While this confirmed that the runner exited with a nonzero code on uncaught exception, it provided zero
empirical evidence that `cleanupAllAsync()` would successfully kill an actively listening production
server and release OS resources under actual test failure conditions.
Additionally, `cleanupAllAsync()` logged a warning on lingering processes rather than raising an observable
cleanup error, violating the requirement that cleanup failures must be explicitly observable.

Corrective Engineering Applied:
1. Controlled Failure Trigger Repositioning:
   - Removed the pre-startup failure trigger from line 411 of `scripts/production_smoke.ts`.
   - Placed the negative test trigger (`SMOKE_FAIL_AFTER_READY=1` and `SMOKE_FORCE_FAIL=1`)
     strictly AFTER `await waitForServerReady(serverProcess, port)`.
   - Guaranteed that the production server is running, listening, and has returned HTTP 200 on `/health`
     before any simulated assertion failure is triggered.
2. Observable Cleanup Failures:
   - Hardened `cleanupAllAsync()`: If registered processes remain alive after the bounded SIGKILL
     interval (3000ms), it now logs and throws a descriptive `[Cleanup Failure]` error.
   - Preserved error logging in the runner's top-level `.catch()` block: logs the primary assertion
     failure first, attempts cleanup, logs any cleanup errors, and exits with code 1.
3. Dedicated Integration Test Harness (`scripts/test_failure_cleanup.ts`):
   - Spawns the production smoke runner with `SMOKE_FAIL_AFTER_READY=1`.
   - Captures and validates stdout, stderr, exit code, and execution duration.
   - Asserts non-zero exit code (`code === 1`, `signal === null`).
   - Extracts dynamically allocated ephemeral port and server PID from runner logs.
   - Verifies the strict chronological sequence: readiness confirmation index < failure trigger index < assertion failure index.
   - Validates OS-level process termination using `process.kill(serverPid, 0)` (verifying `ESRCH`).
   - Validates Linux kernel `/proc/${serverPid}` filesystem absence.
   - Validates zero lingering descendant/child processes via `/proc/*/status` PPID inspection.
   - Probes port release via TCP socket connection and actively binds a fresh `net.createServer()`
     to prove immediate re-usability of the ephemeral port.
   - Confirms that the primary assertion failure was preserved in the log output without truncation or concealment.
4. Repository Integration:
   - Added `"test:failure-cleanup": "tsx scripts/test_failure_cleanup.ts"` to `package.json`.
   - Integrated `Failure cleanup integration test` step into `.github/workflows/ci.yml`.

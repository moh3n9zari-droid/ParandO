1. MISSION OVERVIEW & GAPS REMEDIATED
--------------------------------------------------------------------------------
Objective:
Close the remaining two verification risks in P0-01 failure-cleanup:
1. Replace direct-child checks (`getLinuxDescendantPids`) with complete recursive
   descendant hierarchy inspection and process-group (PGRP) enumeration.
2. Resolve the integration harness timeout orphan risk: ensure the timeout handler
   cleans up BOTH the runner process group AND the independently detached production
   server process group.
3. Revert unrelated `onunhandledrejection` interceptors from `index.html`.
4. Provide dedicated regression test coverage for the timeout cleanup path and observable
   cleanup failure reporting.

Root Cause Analysis of the Identified Risks:
1. In Linux, child processes can spawn grandchildren or deeper worker processes. Checking
   only `PPID === serverPid` catches direct children but misses grandchildren and deeper
   descendants. Furthermore, detached servers run in their own process group (`pgrp === serverPid`).
   Direct-child checking alone was insufficient to guarantee zero surviving processes in the group.
2. The integration test harness timeout path previously dispatched `SIGKILL` only to `child.pid`
   (the smoke runner). Because `spawnProductionServer` starts `server.ts` with `detached: true`,
   the server runs in its own process group (`-serverPid`). If the runner hung, killing only the
   runner process group left the detached server group running as an orphan in the OS.

Corrective Engineering Applied:
1. Reversion of Unrelated Changes:
   - Reverted the `onunhandledrejection` listener and property setter override from `index.html`.
2. Comprehensive Process Tree & Group Inspection (`scripts/process_tree.ts`):
   - Implemented `getProcStatInfo(pid)` parsing `/proc/[pid]/stat` (extracting PPID and PGRP).
   - Implemented `getLinuxProcessGroupPids(pgid)` to enumerate all processes in a given PGID.
   - Implemented `getRecursiveDescendants(rootPid)` via BFS on the parent-to-children graph.
   - Implemented `getAllTrackedProcesses(pgid, rootPid)` combining root, group, and descendants.
   - Implemented `terminateProcessGroupGracefully(pgid, rootPid, timeoutMs)` ensuring bounded
     escalation to SIGKILL and OS confirmation.
   - Implemented `assertZeroLingeringProcesses(pids, context)` throwing observable `[Cleanup Failure]`.
3. Deterministic Harness Timeout Cleanup (`scripts/test_failure_cleanup.ts`):
   - Streams runner stdout and continuously parses `port`, `serverPid`, and `serverPgid`.
   - On timeout, terminates BOTH `serverPgid` (detached server group) AND `runnerPgid` (runner group).
   - Actively probes port release and re-binds a fresh TCP socket to confirm port recovery.
   - Verifies zero surviving processes across both process groups.
4. Dedicated Timeout-Cleanup Regression Suite (`scripts/test_timeout_cleanup.ts`):
   - Case 1: Spawns runner with `SMOKE_HANG_AFTER_READY=1`, verifies readiness, triggers timeout,
     and proves complete termination of runner, server, process group, descendants, and port release.
   - Case 2: Proves lingering process detection failure is explicitly observable with diagnostic PIDs.
5. Repository & CI Integration:
   - Added `"test:timeout-cleanup": "tsx scripts/test_timeout_cleanup.ts"` in `package.json`.
   - Added `Timeout cleanup regression test` step in `.github/workflows/ci.yml`.

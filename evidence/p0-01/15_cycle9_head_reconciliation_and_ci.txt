3. VITE HMR INVESTIGATION AND NARROWING REPORT
--------------------------------------------------------------------------------
Reported Errors:
- `[vite] createWebSocketModuleRunnerTransport/connect/</<@https://.../@vite/client:454:22`
- `Error: WebSocket closed without opened.`

Root Cause:
In the hosted AI Studio dev preview environment, the outer Cloud Run reverse proxy terminates HTTPS and forwards HTTP traffic to the application on port 3000. It does not forward arbitrary WebSocket connections on root path `/`. Vite's `@vite/client` runtime initiates an HMR WebSocket connection to `wss://<host>/?token=...`. When the preview proxy terminates or drops this non-HTTP connection, `@vite/client` fires a `close` event before `open`, rejecting the promise inside `createWebSocketModuleRunnerTransport` at line 454.

Investigation of Previous Mitigation:
In commit 365247d9da150ae48f851a0d4c5c95470731290a, a global error interception handler was added to `index.html`. It intercepted `console.error`, `window.error`, and `unhandledrejection` with broad checks:
`if (msg.includes('WebSocket') || msg.includes('vite') || ...)`
This broad filtering was identified as an anti-pattern because it would silence legitimate application-level WebSocket errors (e.g., disconnection or protocol errors in `/ws` auction connections).

Remediation Applied in Cycle 9:
The handler in `index.html` was refactored and strictly narrowed:
1. Only errors originating from `@vite/client`, `createWebSocketModuleRunnerTransport`, or containing `WebSocket closed without opened.` are handled as preview-environment HMR transport limitations.
2. Legitimate application WebSocket errors on `/ws`, auction bidding errors, and financial state transitions are completely preserved and never suppressed.
3. In `server.ts`, `server.on('upgrade', ...)` forwards `/ws` requests to `wss.handleUpgrade` and cleanly delegates other upgrade requests to registered listeners (such as Vite) without destroying sockets.
